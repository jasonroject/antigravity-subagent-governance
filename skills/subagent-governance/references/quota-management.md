# 子代理配额与生命周期

## 能力探测

host-governor 是可选宿主能力。派发前先探测它是否存在，并确认返回值包含总额度、已用额度和租约标识。文档中的接口名只是能力示例，不能假设每个 Antigravity 环境都提供同名 MCP 工具。

没有可用配额服务时，使用当前环境明确允许的保守上限。未知上限按 1 个活跃子代理处理，不通过并发猜测绕过限制。

## 租约流程

1. 读取全局和模型维度的剩余额度。
2. 原子申请带 TTL 的租约，记录父任务、任务 ID、模型和写集。
3. 申请失败时不派发，向主 Agent 返回原因。
4. 启动子代理失败时立即幂等释放租约。
5. 用 try/finally 释放租约。取消、超时、工具异常和父任务结束都走同一清理路径。
6. TTL 到期后由宿主回收。重复释放必须安全。

排队中的任务不占用活跃槽位，除非宿主明确规定。嵌套子代理必须计入同一全局额度，不能通过子代理继续派发绕过上限。

## 终止条件

每个任务都必须有最大运行时长、最大输出量和取消操作。超过任一限制时停止任务并返回 timed_out 或 cancelled 状态。主 Agent 汇报前必须列出仍在运行的任务，或明确没有可回收状态。
